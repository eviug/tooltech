# Tooltech Technologies - static HTML site (for GitHub Pages)

Plain HTML, CSS and JavaScript. No PHP and no server needed.

## Put it on GitHub Pages
1. Create a repository and upload everything in this folder (keep `CNAME` and `.nojekyll`).
2. Repository Settings > Pages > deploy from the `main` branch, root folder.
3. Your custom domain comes from the `CNAME` file (tooltechtechnologies.online).

## Changing things
The pages are generated by `build.py` (needs Python 3 only). After any change run:

    python3 build.py

then commit and push.

| I want to...                         | Edit                                    |
|--------------------------------------|-----------------------------------------|
| add / change / remove a product      | the `PRODUCTS` list in `build.py`       |
| change phone, WhatsApp, email        | `CFG` in `build.py`, and the numbers in `src/*.html` |
| write a blog post                    | add a file to `posts/` (below)          |
| change text on Home/About/Services/Projects | `src/index.html`, `src/about.html`, ... |
| colours and layout                   | `style.css`                             |

### Blog post file (posts/my-post-title.md)
```
---
title: My post title
date: 2026-10-20
excerpt: One or two sentences shown on the blog list.
image: img/it-lab.webp
tags: Repair, Tips
---
Text here. Use ## for headings, - for bullets, **bold**, [a link](shop.html).
```

## Contact form
Static sites cannot send email by themselves, so by default the form opens the visitor's
email app with the message addressed to tooltechtechnologies@gmail.com.
For direct delivery, make a free form at formspree.io, paste its address into
`FORM_ENDPOINT` at the top of `contact.js`, and the message is sent straight to your inbox.

## Security measures kept in the static version
- Content-Security-Policy on every page: only the site's own scripts run, no inline scripts.
- All text is escaped by `build.py` before it is written to a page; blog posts are rendered by a safe
  Markdown converter (raw HTML shown as text, only http(s), mailto and own-page links allowed).
- In the browser, user text (search box, cart form, URL values) is only ever inserted as text, and URL
  filter values are checked against whitelists. Cart data from storage is validated.
- Contact form: validation, honeypot field, minimum time, values URL-encoded (no mail-header injection).
- Limits of static hosting: GitHub Pages does not let you set HTTP headers (such as X-Frame-Options), and
  there is no server-side code, so measures like CSRF tokens and rate limiting do not apply here.
